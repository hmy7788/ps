> ⚠️ 이 문제는 실제 시험 문제를 그대로 옮긴 것이 아니라, 시험 직후 남긴 기억과 A4 풀이 흔적을 바탕으로 역으로 복원한 것입니다. 주어진 입출력 예시 2개를 실제로 코드로 검증했지만, 세부 표현(변수명, 제약사항 범위 등)은 실제 문제와 다를 수 있습니다.

## 문제 설명

1~n번, 총 n개의 가상 서버를 운영하고 있습니다. 서버들을 연결하는 통신 선로 후보들이 `networks` 배열로 주어지며, 각 원소 `[a, b, weight]`는 서버 `a`와 `b`를 잇는 가중치 `weight`짜리 선로 후보를 의미합니다. 같은 두 서버 사이에 여러 개의 선로 후보가 존재할 수 있습니다.

다음 두 조건을 모두 만족하도록 활성화할 선로를 선택해야 합니다.

1. **실시간 데이터 동기화**: `server_pair`로 주어지는 서버 쌍들은 반드시 **다른 서버를 거치지 않는 직접 연결 선로**가 1개 이상 활성화되어 있어야 합니다.
2. **네트워크 슬림화**: 모든 서버가 (직접 또는 간접적으로) 서로 통신 가능해야 하며, 이때 **활성화된 선로의 총 개수가 최소**가 되어야 합니다. (= 스패닝 트리를 구성)

이 조건을 만족하는 네트워크를 구성할 때, 활성화된 선로들의 가중치 **합이 가장 작은 경우**와 **가장 큰 경우** 각각의 총합을 `[최소, 최대]` 형태로 return 하도록 `solution` 함수를 완성해 주세요.

## 파라미터

| 이름 | 타입 | 설명 |
|---|---|---|
| `n` | 정수 | 서버 개수 (1 ~ n번) |
| `networks` | 2차원 배열 | `[a, b, weight]` 형태의 선로 후보 목록 |
| `server_pair` | 2차원 배열 | 반드시 직접 연결되어야 하는 서버 쌍 목록 |

## 제한사항

- 제약사항 상세 범위는 정확히 기억나지 않음 (※ 확인 필요)
- `networks`에는 동일한 서버 쌍을 잇는 선로가 여러 개 존재할 수 있음 (예시 1의 `[2,3,100]`, `[2,3,2000]`)

## 입출력 예

| n | networks | server_pair | result |
|---|---|---|---|
| 4 | [[1,2,30],[2,3,100],[2,3,2000],[3,4,20]] | [[1,2],[2,3]] | [150, 2050] |
| 6 | [[1,2,16],[1,3,4],[2,3,11],[2,3,8],[2,4,12],[3,5,7],[4,6,10],[5,6,1]] | [[2,3],[5,6],[3,5]] | [30, 47] |

## 입출력 예 설명

### 입출력 예 #1

`server_pair`가 `[1,2]`, `[2,3]`이므로 이 두 쌍은 반드시 직접 간선으로 연결되어야 합니다.

- `(1,2)`는 후보가 `30` 하나뿐이라 선택의 여지가 없음
- `(2,3)`은 후보가 `100`과 `2000` 두 개 → **최소** 계산 시 `100`, **최대** 계산 시 `2000` 선택

이렇게 1,2,3이 강제로 묶이고 나면, 남은 서버 `4`를 연결할 선로는 `(3,4,20)` 하나뿐이라 자동으로 포함됩니다.

- **최소**: 30 + 100 + 20 = **150**
- **최대**: 30 + 2000 + 20 = **2050**

### 입출력 예 #2

`server_pair`가 `[2,3]`, `[5,6]`, `[3,5]`이므로 이 세 쌍은 반드시 직접 연결됩니다.

- `(2,3)`은 후보가 `11`, `8` 두 개 → 최소 계산 시 `8`, 최대 계산 시 `11`
- `(5,6)`은 후보가 `1` 하나뿐
- `(3,5)`는 후보가 `7` 하나뿐

이 세 강제 간선으로 `{2,3,5,6}`이 하나로 묶이고, 남은 서버 `1`, `4`를 마저 연결해야 합니다 (n-1=5개의 선로가 필요하므로 2개 더 필요).

**최소 합을 만들 때** (남은 두 자리도 가장 작은 값으로 채움):
- `1` 연결: `(1,2,16)` vs `(1,3,4)` → 더 작은 `4` 선택
- `4` 연결: `(2,4,12)` vs `(4,6,10)` → 더 작은 `10` 선택
- 합계: 8(2-3) + 1(5-6) + 7(3-5) + 4(1-3) + 10(4-6) = **30**

**최대 합을 만들 때** (남은 두 자리도 가장 큰 값으로 채움):
- `1` 연결: `(1,2,16)` vs `(1,3,4)` → 더 큰 `16` 선택
- `4` 연결: `(2,4,12)` vs `(4,6,10)` → 더 큰 `12` 선택
- 합계: 11(2-3) + 1(5-6) + 7(3-5) + 16(1-2) + 12(2-4) = **47**

## 접근 방향 메모

- 겉으로는 그냥 **MST(최소 스패닝 트리)** 문제처럼 보이지만, 일반 크루스칼 알고리즘을 그대로 돌리면 `server_pair`로 지정된 쌍이 간접 경로로 연결되어버려서 "직접 연결" 조건을 놓칠 수 있음
  - 실제로 예시 2에서 최댓값을 구할 때, 일반적인 "최대 스패닝 트리"(가중치 큰 것부터 그리디하게 선택)를 그냥 적용하면 `(5,6)` 쌍이 직접 간선 대신 `4→6`, `3→5` 등 다른 경로로 간접 연결되어버려서 합이 56이 나옴 (오답). "직접 연결"을 강제해야 정답인 47이 나옴
- **정확한 접근**: Union-Find를 이용한 크루스칼 알고리즘을 쓰되,
  1. `server_pair`에 있는 쌍들을 **먼저 강제로 union** (중복 간선이 있으면 목적에 따라 최솟값/최댓값 선택)
  2. 이후 나머지 간선들을 가중치 오름차순(최소용) 또는 내림차순(최대용)으로 정렬해서 일반 크루스칼처럼 스패닝 트리를 완성
  3. 최소용/최대용을 각각 계산해서 `[최소합, 최대합]`으로 반환
- "먼저 특정 간선을 강제로 포함시키고 나머지를 크루스칼로 채운다"는 패턴은 MST 응용 문제에서 종종 나오는 테크닉이라, 알아두면 비슷한 유형에 도움될 듯
