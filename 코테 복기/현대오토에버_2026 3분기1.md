> ⚠️ 이 문제는 실제 시험 문제를 그대로 옮긴 것이 아니라, 시험 직후 A4에 남긴 풀이 흔적과 기억을 바탕으로 **역으로 복원**한 것입니다. 주어진 입출력 예시 3개를 직접 시뮬레이션해서 검증했지만, 세부 표현(변수명, 제약사항 범위 등)은 실제 문제와 다를 수 있습니다.

## 문제 설명

`dataSize`와 `processingTime`이라는 두 배열이 주어집니다. `dataSize[i]`는 `i`번째 데이터의 크기, `processingTime[i]`는 해당 데이터를 처리하는 데 걸리는 시간입니다.

데이터는 인덱스 순서대로, **시각 `i`(0부터 시작)에 하나씩 도착**합니다. 데이터가 도착하면 다음 규칙에 따라 서버에 할당합니다.

1. 현재 **사용 가능한**(이전 작업이 끝난) 서버들 중, 지금까지의 **누적 처리량**(그 서버가 처리한 데이터 크기의 합)이 **가장 작은 서버**를 선택합니다.
2. 누적 처리량이 가장 작은 서버가 여러 개라면, 그중 아무 서버나 선택합니다.
3. 사용 가능한 서버가 하나도 없다면, **새로운 서버를 생성**하여 그 데이터를 할당합니다.

데이터를 할당받은 서버는 할당 시각부터 `processingTime[i]`만큼의 시간 동안 사용 중 상태가 되며, 이 기간이 지나야 다시 사용 가능한 상태가 됩니다. 동시에 해당 서버의 누적 처리량에는 `dataSize[i]`가 더해집니다.

모든 데이터의 할당이 끝난 뒤, **각 서버의 최종 누적 처리량 중 최댓값**을 return 하도록 `solution` 함수를 완성해 주세요.

## 제한사항

- 1 ≤ `dataSize`의 길이 ≤ 200,000
- `dataSize`의 길이 = `processingTime`의 길이
- `dataSize[i]`, `processingTime[i]`의 값 범위는 정확히 기억나지 않음 (※ 확인 필요)

## 입출력 예

| dataSize | processingTime | result |
|---|---|---|
| [4, 4, 2, 2, 3, 1, 5, 2] | [4, 2, 4, 1, 2, 1, 1, 1] | 9 |
| [3, 1, 4] | [1, 1, 1] | 8 |
| [2, 7, 4] | [5, 5, 5] | 7 |

## 입출력 예 설명

### 입출력 예 #1

| 시각(t) | 도착 데이터 (size, pt) | 사용 가능 서버 (번호: 누적량) | 선택된 서버 | 서버 상태 갱신 |
|---|---|---|---|---|
| 0 | (4,4) | 없음 | 새 서버 S1 생성 | S1: 누적4, ~t=4 |
| 1 | (4,2) | 없음 (S1 사용중) | 새 서버 S2 생성 | S2: 누적4, ~t=3 |
| 2 | (2,4) | 없음 (S1,S2 사용중) | 새 서버 S3 생성 | S3: 누적2, ~t=6 |
| 3 | (2,1) | S2(4) | S2 | S2: 누적6, ~t=4 |
| 4 | (3,2) | S1(4), S2(6) | S1 (누적 더 작음) | S1: 누적7, ~t=6 |
| 5 | (1,1) | S2(6) | S2 | S2: 누적7, ~t=6 |
| 6 | (5,1) | S1(7), S2(7), S3(2) | S3 (누적 가장 작음) | S3: 누적7, ~t=7 |
| 7 | (2,1) | S1(7), S2(7), S3(7) | 아무거나(S1) | S1: 누적9, ~t=8 |

최종 누적량: S1=9, S2=7, S3=7 → **최댓값 9**

### 입출력 예 #2

| 시각(t) | 도착 데이터 (size, pt) | 사용 가능 서버 | 선택된 서버 | 갱신 |
|---|---|---|---|---|
| 0 | (3,1) | 없음 | 새 서버 S1 생성 | S1: 누적3, ~t=1 |
| 1 | (1,1) | S1(3) | S1 | S1: 누적4, ~t=2 |
| 2 | (4,1) | S1(4) | S1 | S1: 누적8, ~t=3 |

서버 1개만 사용 → **최댓값 8**

### 입출력 예 #3

| 시각(t) | 도착 데이터 (size, pt) | 사용 가능 서버 | 선택된 서버 | 갱신 |
|---|---|---|---|---|
| 0 | (2,5) | 없음 | 새 서버 S1 생성 | S1: 누적2, ~t=5 |
| 1 | (7,5) | 없음 (S1 사용중) | 새 서버 S2 생성 | S2: 누적7, ~t=6 |
| 2 | (4,5) | 없음 (S1,S2 사용중) | 새 서버 S3 생성 | S3: 누적4, ~t=7 |

최종 누적량: S1=2, S2=7, S3=4 → **최댓값 7**

## 접근 방향 메모

- **그리디**: 매 시각마다 "사용 가능한 서버 중 누적량 최소"를 즉시 선택 (전체를 다시 최적화하지 않고 그 순간의 최선을 선택)
- 사용 가능/불가능 서버를 매번 전체 순회로 판별하면 `O(N × 서버수)`가 되어 `dataSize` 길이 200,000 기준으로 시간 초과 우려 → **우선순위 큐(최소 힙)**로 "사용 가능 서버 중 최소 누적량"을 빠르게 뽑는 최적화가 필요해 보임
- 손필기에 `check_use_server()` 같은 함수와 `servers.append([dataSize[t], t+pt[t]])` 형태의 구조가 보이는 걸로 봐서, 서버를 `[누적량, 사용종료시각]` 형태로 관리한 것으로 추정
